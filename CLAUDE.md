# NYC Schools Agentic

Interactive school-data site/server for NYC public schools. Serves HTML pages to humans **and an MCP server to agents** at `/mcp/` (Streamable HTTP) — A2A / ACP surfaces are planned siblings. Agents are intended consumers, not an afterthought. Live runtime, not a static build.

## Architecture

### Two-phase data flow

```
upstream sources   →   school-data/   →   data/   →   running app
              (fetch_data.py)     (build_db.py)
                [build only]      [committed via Git LFS]
```

The running app has **zero runtime dependency** on the upstream `nycschools` package or on `school-data/`. It reads from `data/data.sqlite` (LFS-tracked) plus a few small geo / CSV files in `data/` (school locations, school-zone polygons, NTA boundaries, co-location report). Cold-start data load is ~1.5s, on the lifespan critical path. `analytics.warm_caches()` runs in a background thread (`asyncio.to_thread`) — `/healthz` returns the moment uvicorn binds and reports the warm state (`caches_warming`, `caches_warm_s`). Warm-up takes ~10s locally and ~40s on Fly's `performance-1x`; the first user hit to `/`, `/neighborhood/*`, or any other heavy aggregation may arrive mid-warm and pay an un-amortized cost, but every request after is cached. Re-blocking warm on the lifespan regressed prod to 230s with healthcheck flap on `shared-cpu-1x` — don't.

The data refresh workflow (`scripts/fetch_data.py` + `scripts/build_db.py`) runs locally, rarely (~once a year when NYSED publishes a new School Report Card), then commits the rebuilt `data/` files. Production never re-pulls; every refresh is a deliberate, reviewable git commit. See README "Refreshing data" for the full sequence.

This repo is **AGPL-3.0** to match upstream. Every deployed surface is a network service under AGPL §13, so the site footer links to corresponding source on GitHub.

### The keystone: unified service layer

Every data-access operation is defined **once** as a transport-agnostic Python function in `app/services/`. The function takes primitives and returns Pydantic models — no FastAPI Request, no MCP Context, no transport leakage. Thin adapters in `app/web/` and `app/mcp_server/` (and, later, A2A / ACP servers) wrap those functions for each protocol.

```
                 search_schools(query) -> list[SchoolSummary]
                              |
       ┌──────────┬───────────┼───────────┬──────────┐
       v          v           v           v          v
     /search   /school/X    /mcp/      /a2a       /acp
     (HTML)    (HTML)       (tool)     (skill)    (handler)
```

A new operation (e.g. `list_by_attendance_zone`) shows up across all surfaces by editing one file. **Never import transport types into `services/`.**

Same pattern powers cross-surface reuse in concrete cases that already shipped: `top_schools` is both an MCP tool *and* drives the homepage school leaderboards; `aggregate_by_neighborhood` is both an MCP tool *and* drives the homepage NTA leaderboards; `school_peers` is both an MCP tool *and* renders the "Schools Nearby" section on the school page; `get_neighborhood` is both an MCP tool *and* powers the `/neighborhood/{nta}` page. Adding a new surface (e.g. an `/api/v1/...` JSON layer or A2A) is a matter of writing a new adapter directory next to `web/` and `mcp_server/`, not new business logic.

## Repo boundaries

The upstream **`nycschools`** package (Matthew X. Curinga / Adelphi Ed Tech, AGPL-3.0) is treated as **read-only / upstream-track**. We work against our **fork at `github.com/kleinmatic/nycschools`** for any data-layer additions. Three branches currently have new loaders pending PR back to Adelphi: `nysed-src-loader` (NYSED Report Card Database), `staffing-loader` (Guidance Counselor + Social Worker FTE counts), and `ms-directory-loader` (Middle School Directory with per-program admission methods).

Upstream nycschools is a **build-time-only** dependency — used by `scripts/fetch_data.py` and `scripts/build_db.py` to assemble `data/`, never imported by the running app.

| Goes upstream (kleinmatic/nycschools fork → PR to Adelphi) | Goes here |
|---|---|
| New data loaders, schema fixes, dataset modules | Service-layer functions over the SQLite |
| Bug fixes in existing loaders | HTTP / MCP / A2A / ACP route adapters |
| New tests for the data layer | Tests for service & route layers |
| Documentation for the package itself | Site templates, frontend, deploy, project notes |

When in doubt: if another NYC-schools-data project could reuse it, it's upstream. Otherwise it's here.

## Build-time data source reference

Used only by `scripts/fetch_data.py` and `scripts/build_db.py`, never at runtime:

- `schools.load_school_demographics()` — demographics by DBN/year (race %, ELL, SWD, poverty, ENI, enrollment)
- `schools.search(df, qry)` — fuzzy school lookup; we inline an equivalent in `app/services/schools.py` so runtime doesn't need this import
- `exams.load_math()` / `load_ela()` — NYS grades 3-8 state tests
- `exams.load_regents()` — NYS Regents exams
- `class_size.load_class_size()` / `load_ptr()` — class size + pupil:teacher ratio
- `snapshot.load_snapshots()` — DOE official snapshot (attendance, chronic absence, principal, admissions method, quality review)
- `geo.load_school_locations()` / `load_zipcodes()` / `load_neighborhoods()` — point/polygon geodata
- `schools.load_hs_directory(ay)` — HS programs and admissions criteria
- `shsat.load_admission_offers()` — SHSAT outcomes by sending school
- `budgets.load_galaxy_budgets()` — Galaxy budget portal scrape
- `nysed_src.load_*()` (on the `nysed-src-loader` branch of `kleinmatic/nycschools`) — NYSED School Report Card Database: ESSA accountability, chronic absenteeism, per-pupil expenditures, teacher quality, HS graduation rate, CCCR
- `staffing.load_staffing(ay)` (on the `staffing-loader` branch of `kleinmatic/nycschools`) — DOE annual Guidance Counselor + Social Worker FTE report from InfoHub. Per-school GC / SW FTE counts plus DOE-computed pupils-per-staff ratios.
- `ms_directory.load_ms_directory(ay)` (on the `ms-directory-loader` branch of `kleinmatic/nycschools`) — NYC DOE annual Middle School Directory from InfoHub. **Long format**: one row per (DBN, program) — schools commonly carry 1-4 programs each with its own `admission_method` (one of: Open, Zone Priority, Zoned Only, Screened, Screened With Assessment, Language Criteria, Audition, Talent Test, ASD/ACES Program, D75 Special Education Inclusive Services) and a priority cascade. Source xlsx hits an SSL chain locally for some Python builds; `scripts/fetch_data.py` downloads via requests then passes the local path to `load_ms_directory(path=...)` so the build survives those envs.

Two non-upstream geo / CSV data files we fetch ourselves (NYC Open Data Socrata endpoints): the 2024-25 ES + MS attendance-zone polygons (`scripts.fetch_data.fetch_zone_polygons`), the 2020-21 Co-Location Report (`fetch_co_location` → `data/co-locations.csv`), and the 2010 NTA polygon set (`fetch_nta_polygons` — pulled from a GitHub mirror because NYC retired the 2010 NTA dataset from Open Data when 2020 NTAs shipped, but `school-locations.geojson` still uses 2010-era NTA names).

The upstream bulk-archive Drive URL is dead; we lazy-fetch per file from `data.mixi.nyc` instead. NYSED publishes its database as a Microsoft Access `.mdb` inside a ZIP, requiring `mdbtools` to extract — see README "Refreshing data" prerequisites.

## Conventions

- **DBN is the primary key** everywhere. URLs use it: `/school/15K321`.
- **Neighborhood = NTA (Neighborhood Tabulation Area).** NYC's 195 official neighborhood boundaries — the closest formal proxy to colloquial neighborhood names. Per-school NTA name lives in `data/school-locations.geojson` (`nta_name` column); 93% coverage. **District = the natural "zone"** (1-32, geographic). The pair powers `aggregate_by_neighborhood`, `school_peers(scope="district")`, the homepage "By place" section, and the school page "Schools nearby" section. HS is city-wide choice — district-as-zone is meaningful for ES/MS only.
- **Active schools = latest demographics row `ay >= 2022`.** Closed/inactive schools have ancient demographics rows with sentinel zeros (e.g. ENI=0 in 2005 export); excluding them keeps leaderboards from being polluted by zombie schools. Filter applied in `_candidate_schools` in `analytics.py`.
- **`demographics.beds` is `int64`; NYSED `ENTITY_CD` is a 12-char string.** Always convert to zero-padded string before joining. Helper: `_beds_to_str` in `analytics.py`. Direct `==` between the two silently fails to match.
- **ENI is the equity proxy of choice for ranking and peer comparison; `poverty_pct` is for direct interpretability.** Don't rank schools by `poverty_pct` — NYC's 2017 CEP transition broke that signal's continuity. Detail in README "ENI vs poverty_pct". The full 13-metric vocabulary used by `top_schools` / `bulk_metrics` / `top_neighborhoods` lives in `METRIC_DESCRIPTIONS` in `analytics.py` — single source of truth surfaced into MCP tool descriptions and README.
- **D75 is derived from `district == 75`**, exposed as `SchoolSummary.is_d75`. District 75 is NYC's citywide specialized special-ed district; placement is by the Committee on Special Education (not by zone or choice) and accountability is reported under different rules. The flag drives the amber pill badge on the school page and the placement caveat in `school_swd_outcomes(...).notes`. Don't treat D75 schools as peers of comprehensive schools in leaderboards or peer-rank cohorts. The DBN's "75" prefix is perfectly correlated with `district == 75`, but the column is the source of truth.
- **MS admission is district-based choice, NOT strict zoning** — the most common modeling mistake in this data. `find_schools_for_address` returns school-specific zone-priority polygon matches (numeric `label` like "297") in `middle`, but that's a priority *tier* within a district-choice process, not a placement. Read `ms_admission_type` to interpret: `zone_priority_choice` = address falls in a school-priority polygon; `district_choice` = address only hits a whole-district fallback polygon (label like `D15`). The `ms_admission_note` is a pre-composed string telling the consumer to follow up with `schools_in_district(ms_district, level="middle")`. **Important about priority cascades**: across multiple D2 schools, "residents of the middle school zone" is priority **4** (below siblings, district residents, NYC residents) — NOT priority 1. Never assert "you're in the top priority tier" — surface the published priority strings verbatim and let the consumer read them. Source of truth for per-school MS admission methods is `store.ms_directory` (the Fall-2025 InfoHub xlsx, long-format: one row per (DBN, program)). The 10 method values: Open, Zone Priority, Zoned Only, Screened, Screened With Assessment, Language Criteria, Audition, Talent Test, ASD/ACES Program, D75 Special Education Inclusive Services. A single school commonly carries multiple programs with different methods (M.S. 131 has Zone Priority + Language Criteria + Screened + ASD/ACES under one DBN). The MS Directory is the **authoritative cohort** for "what MS schools exist in District X" — broader than `demographics.school_level == "middle"`, which excludes K-8 and 6-12 schools that enroll middle-school students. Don't use the demographics filter for MS rollups.
- **`schools_in_district(district, level)` is the answer to "tell me about district N {middle | elementary | high} schools."** For `level="middle"` it joins the MS Directory with demographics — each school's `admission_methods` lists the methods it admits by, and `ms_programs[*].priorities` carries the per-program cascade strings as published. Pairs with `find_schools_for_address`: when that returns `ms_admission_type in {"zone_priority_choice", "district_choice"}`, `schools_in_district(ms_district, "middle")` is the follow-up. For `level="elementary"`/`"high"` the result is a basic listing with an `admission_overview` note — ES has no MS-shaped directory, HS is city-wide choice (so district grouping is geographic-only). D75 + middle falls back to the basic listing — D75 schools aren't in the MS Directory because their placement is by the Committee on Special Education.
- **NYSED subgroup tables (`nysed_chronic`, `nysed_hs_grad`, `nysed_hs_cccr`, `nysed_essa_subgroup`) carry every subgroup; consumers must filter.** Existing helpers in `schools.py` (`_chronic_for`, etc.) return all subgroups mixed — the All-Students-only views downstream (analytics rank metrics, exam tables) filter to `SUBGROUP_NAME == "All Students"`. The SWD-outcomes path filters to `"Students with Disabilities"`. The literal `"s"` suppression sentinel becomes NaN at load time; combined with cohort_count, that's how `school_swd_outcomes` distinguishes "suppressed" from "missing".
- **Don't import transport types into `app/services/`.** Functions take primitives and return Pydantic models. The adapter wraps; the service computes.
- **Async at the edge, sync inside.** FastAPI routes are `async def`; service functions are sync (pandas isn't async). That's fine — they don't block long enough to matter.
- **Don't commit secrets.** `SECRETS.md` and several other patterns are gitignored; deploy keys, vendor info, scratch SQL go there or in a sibling private repo (see README "License & private state").
- **Don't bypass the SQLite at runtime.** If a new data source is needed, add it to the upstream fork (or to this repo if it's truly app-specific), surface it through `scripts/build_db.py`, and read it via `app/data.py`. The running app should never call upstream loaders or hit the network for static data.
- **`scripts/find_school.py` and `scripts/inspect_school.py`** still use the upstream loaders directly (pre-SQLite design). They're useful for ad-hoc inspection of raw upstream data; require `uv sync --group build` to run.
- **Client-side dataviz uses Observable Plot** (UMD via CDN in `base.html`, with d3 alongside since Plot's UMD doesn't re-export d3 helpers). Server-side shaping lives in `app/web/charts.py` — same boundary rule as templates: takes service-layer Pydantic models, returns chart-ready plain dicts. Pass to Jinja contexts and inline `<script>` with `| tojson`. The school-page grade × year × proficiency-level chart is the canonical example: per-cell stacked bars, a NYC '22 cohort comparator column at reduced opacity, and a gray cell placeholder for COVID-cancelled (AY 2019, 2020) years. It is **split into two blocks at the 2023 standards divide** (see the grades-3-8 standards-split rule below); the NYC-'22 comparator and the COVID cells live only in the Old-Standard block.
- **GeoJSON fed to Plot.geo / d3 must be rewound clockwise.** d3-geo interprets polygons spherically: an RFC 7946 counterclockwise exterior ring reads as enclosing the whole globe and renders as a solid full-frame fill (the homepage NTA choropleths shipped blank until this was caught). `_orient_for_d3` in `app/web/charts.py` rewinds exteriors CW; shoelace-pinned by `test_homepage_nta_map_exterior_rings_wind_clockwise`. Related: homepage chart payloads (`homepage_citywide`, `homepage_nta_map`) are lru_cached and warmed from `main.py`'s lifespan thread — they can't be warmed from `analytics.warm_caches()` because services must never import the web layer. NTA geometry is simplified (~50m) + coordinate-rounded to keep the inline FeatureCollection near 100KB (payload-size test caps it at 250KB).
- **Every Plot chart passes an explicit `width` measured from its container** (`holder.clientWidth`, with a floor). Plot's default is a fixed 640px SVG, which overflows narrow viewports — grid-cell panels must be appended to the DOM *before* measuring. Related tooling gotcha: headless Chrome clamps `--window-size` width to ~485px, so a "375px mobile" screenshot is actually a 485px layout clipped to a 375px image — don't diagnose overflow from it; probe `document.documentElement.clientWidth` via an injected console.log (readable with `--enable-logging=stderr --dump-dom`).
- **School page displays in tiers** (macros in `school.html`): visible sections for fresh, headline data; `ref_section(id, title, vintage=…)` accordions for reference/stale matter — the vintage pill in the summary line is mandatory for anything older than the latest AY (AY-2021 HS directory, 2022-23 budget/class size; the DOE School Quality Snapshot is now refreshed to SY 2024-25 and still carries a vintage pill); `table_details(label)` demotes every full-history table below its chart. Provenance is one human-readable source line + a methodology popover (filename chips live inside). NYSED subgroup metrics (chronic, grad) get **disparity dot plots, not trend lines** — NYSED publishes only two years, and two points isn't a trend.
- **InfoHub Regents percentages arrive 0-100**, unlike every other pct column (0-1 fractions). `_regents_for` in `services/schools.py` converts at the service boundary (pinned by `test_regents_pcts_are_fractions`); analytics' `_regents_pct_for` normalizes separately. Any new consumer of `store.regents` raw columns must divide by 100 itself.
- **Grades-3-8 exams span a 2023 standards reset — never display across it.** NY replaced the Common Core Learning Standards with the Next Generation Learning Standards; scores and scale scores are NOT comparable across the divide. The boundary is the **fall-year `ay`**: last Common Core administration = spring 2022 = **ay 2021**; first Next Gen = spring 2023 = **ay 2022**. Every grades-3-8 display (school-page chart + full-history tables, homepage proficiency trend) renders as **separate Old-Standard (ay ≤ 2021) / New-Standard (ay ≥ 2022) blocks** — never one shared axis, table, or trend line. Boundary constant `LAST_COMMON_CORE_AY = 2021` in `charts.py` (`exam_grade_year_levels` returns `{"old":…, "new":…}`, `partition_exam_rows` for tables); short heds "Old Standard"/"New Standard", a comparability dek on each, shared footer naming both standards. **Source = standard.** Common Core years (ay ≤ 2021) come from the DOE loaders (`exams.load_ela/load_math`); Next Gen years (ay ≥ 2022) are reshaped from the **NYSED SRC** feathers in `build_db.py` (`_nysed_exam_rows` + `_beds_to_dbn_crosswalk`, All-Students, `ELA3_8`/`MATH3_8` → the "All Grades" row, 0-100 → 0-1). **Year-convention gotcha (cost us a mislabel + a misfiled year):** DOE `ay` is the FALL year (`ay = test_year − 1`); NYSED `YEAR` is the SPRING year, so `_reshape_nysed_exam_feather` does **`ay = YEAR − 1`** to conform. The DOE's own last year (ay 2022 = spring 2023) is *already Next Gen* and would duplicate NYSED's ay 2022, so `build_exam` **drops DOE ay ≥ 2022** — NYSED is the single Next-Gen source (uniform ~1.3k-school coverage). Resulting ay series: 2012..2021 (DOE) then 2022,2023,2024 (NYSED); newest **ay 2024 = SY2024-25**. Pinned by `test_grades_3_8_standards_divide_boundary` + `test_grades_3_8_ay2022_is_next_generation_scale`. **Regents did NOT get this reset** — do not split Regents. Single-latest-year surfaces (leaderboards, peer ranks, neighborhood tables) don't cross the divide and stay whole.
- **Slippy maps use MapLibre GL + CARTO Positron *vector* tiles**, opt-in per template via `base.html`'s `head_extra` block (so only `/neighborhood/{nta}` pays the library cost). **This was Leaflet + CARTO raster PNGs until 2026-08-28.** CARTO began requiring an API key on raster basemaps and started serving unkeyed tiles with an `API KEY REQUIRED` watermark burned into the pixels — HTTP 200, valid PNG, normal byte size, so every status/content-type/size check passed and it reached production unnoticed. **A key does not fix raster:** CARTO's CDN caches by URL path and ignores the `?key=` query param (verified — three different key values returned identical `etag`/`age`/`x-cache: HIT`), so popular tiles keep serving the cached watermarked copy for the 180-day TTL. The fix is the *vector* endpoint, which is keyless, CORS-open, and carries CARTO+OSM attribution in its TileJSON so MapLibre renders the required credit automatically. Duy found the CDN-cache behaviour first while building the demo dashboard. Version pinned to `maplibre-gl@5.0.0` to match that dashboard, which uses the `dark-matter` sibling of the same style — light page gets Positron, dark page gets dark-matter. **Hedge:** the vector endpoint is keyless today for exactly the reason raster was keyless in 2024; CARTO has said raster is being retired, and this buys the demo, not a permanent answer.
- **MapLibre gotchas the Leaflet version didn't have.** (a) **Coordinates are `[lng, lat]`**, the reverse of Leaflet — getting it backwards puts NYC in the Indian Ocean. (b) **Gate layer setup on `styledata`, never `load`.** `load` fires only after the first *rendered frame*, and rendering is driven by `requestAnimationFrame`, which browsers suspend for hidden/background tabs — a map built in a background tab would never attach its boundary or markers. `styledata` fires as soon as the style JSON parses, and `addSource`/`addLayer` are valid from that point. Markers are DOM overlays and need neither. (c) **No `L.geoJSON().getBounds()`**, so bounds are a hand-rolled recursive bbox walk; the recursion is depth-agnostic, which is what keeps MultiPolygon NTAs (Battery Park City-Lower Manhattan, City Island) working — the old manual coord-flatten assumed Polygon-only and silently produced invalid bounds. (d) **No `L.control`**, so the legend is a positioned child of the map container, which needs `position: relative`. (e) `map.resize()` replaces `invalidateSize()`; `cooperativeGestures: true` replaces `scrollWheelZoom: false`.
- **Verifying a map means looking at rendered pixels, and automation makes that harder than it sounds.** The watermark shipped because every non-visual check passed. But the browser-automation tab runs `hidden`, so `requestAnimationFrame` never fires and a WebGL map paints no frames — the canvas comes back blank and *looks* like a bug that isn't one. Structural facts (marker count and colours, legend, attribution text, layer existence) are readable in a hidden tab; the basemap itself only paints once something forces a composite. Vector tile fetches happen in MapLibre's web workers, so they never appear in the main thread's `performance.getEntriesByType('resource')` — absence there is not evidence.
- **House style for headlines and bylines** follows the ProPublica News Apps style guide at `~/Code/guides/news-apps.md`. Key rules to remember: every headline and subhead in AP title case (capitalize first/last words, capitalize nouns/verbs/adjectives/adverbs/pronouns, lowercase short prepositions and articles); leaderboard / chart / section titles too — not just `<h1>` / `<h2>` (so `_HOMEPAGE_LEADERBOARDS["title"]` in analytics.py also follows AP title case); every news app gets a byline under the top headline ("By Scott Klein · Updated <date>"); sources go under every chart, not in a global "credits" page only. The `/sources` page is the readers' catalog of every dataset and its vintage, linked from the footer.
- **Display helpers in `routes.py`**: `LEVEL_LABELS` + the `{{ value|level }}` filter (turns `"high"` into `"High School"` etc. — internal codes stay raw in MCP and SQLite); `{{ value|pretty }}` (straight ASCII apostrophe → U+2019 curly). Both are display-only — never apply to fuzzy-search input or URL slugs.
- **NTA URL slug convention**: spaces become dashes (`/neighborhood/Park-Slope-Gowanus`). `app/services/analytics._fuzzy_match_ntas` matches dash- and space-form transparently. Apply `|replace(' ', '-')|urlencode` in templates that build NTA links.
- **Typography uses Unicode, not HTML entities.** `—` `←` `→` `’` `©` `↗` go in as literal characters in templates. The exceptions: `&amp;` inside URL query strings in `href` attributes (HTML attribute syntax requirement), `&lt;` for a literal `<` in copy that would otherwise parse as a tag start, and the JS `escapeHtml` map's own output values. Per the style guide.
- **Missing-value cells render `<span class="text-slate-300">N/A</span>`**, not em-dash. Macros (`pct()`, `num()`, `money()`, `fmt()`) return that Markup; inline `or "N/A"` patterns must be rewritten as `{% if %} … {% else %}<span class="text-slate-300">N/A</span>{% endif %}` so the span isn't escaped. Style-guide rule plus visual: light-gray N/A recedes when scanning a column of real numbers.
- **Mixed-year disclosure rule:** if a single page combines metrics from multiple vintages (e.g. neighborhood school-by-school table uses ENI from 2024-25, ELA from 2024-25 (new standard), attendance from ~2016), the section caption must say so. If everything on the page is the same year, no note needed. The 2025-26 staffing data is **mid-year** reporting (DOE publishes in February of the AY) — section heading + provenance call this out explicitly.
- **Per-page meta + OG/Twitter tags.** `base.html` defines `{% block meta_description %}`, `{% block og_title %}`, `{% block og_description %}` with defaults; every concrete page overrides `meta_description` with content-specific copy. Dynamic pages (school, neighborhood) interpolate context into the description so a share preview surfaces the school name or NTA. Required by the style guide ("Every page in an app should have a unique title tag, a unique meta-description tag and the correct social media tags").
- **Neighborhood-page metric set:** the per-school **table** uses the **UNION** of `_PEER_METRICS_BY_LEVEL` entries for every school level represented in the NTA, so a HS in a mostly-ES neighborhood (Forest Hills HS in Forest Hills) doesn't appear empty. The **peer-rank cards** use only the **dominant level's** set, since each card ranks the NTA on one coherent metric. Two separate helpers in `analytics.py`: `_table_metrics_for_neighborhood` vs. `_peer_rank_metrics_for_neighborhood`.

- **Security-audit hardening (2026-07-08) — decisions that must not be "re-fixed" back.** (a) **Rate-limiter IP keying** (`app/ratelimit.py`): `CF-Connecting-IP` (only with a valid edge token) → `Fly-Client-IP` (the Fly proxy sets and overwrites it — unspoofable) → transport peer. It does **NOT** trust `X-Forwarded-For` (Fly *appends* to it, so a client controls the leftmost hop → bucket-rotation bypass). Deliberately **not** the audit's suggested "gate `Fly-Client-IP` behind a token, else `scope['client']`" — `scope['client']` is XFF-derived under `--forwarded-allow-ips='*'`, which we keep at `'*'` for `X-Forwarded-Proto` scheme detection. The publisher keys via `CF-Connecting-IP` (transits Cloudflare); direct clients via `Fly-Client-IP`. (b) Bucket map is an `OrderedDict` with LRU `_evict` (idle-prune, then hard-drop to `max_buckets`) so a live flood can't grow it unbounded / re-run an O(n) prune per request. (c) Edge 301 `Location` path is `quote()`-encoded — a percent-decoded CR/LF would inject a header, a non-latin-1 byte would 500. (d) `_McpBodyLimit` (`app/main.py`): 1 MB request-body cap on `/mcp/*`, **pure ASGI, request-side only** (wraps `receive`, never the SSE response); sits inside both gates so a tokenless oversized POST 401s before its body is read. (e) Service-layer input caps before fuzzy-match / outbound geocode: `search_schools` + `_fuzzy_match_ntas` 128 chars, `geocode` address 256. (f) **MCP error masking**: the server runs `mask_error_details=True`; a `@tool` wrapper (replaces `@mcp.tool`, defined in `server.py`) converts service-layer `ValueError` → `ToolError` — the one exception FastMCP surfaces under masking — so curated bad-argument messages ("unknown metric: … Valid: …") still reach the agent for self-correction while unexpected exceptions stay hidden. Masking happens *inside* the tool runner (below middleware), so the conversion must sit at the tool boundary; `services/` can't import `ToolError` (transport type).
- **WebMCP exposure: four patterns.** (1) **Declarative forms** — exactly 4 spec attributes (`toolname` / `tooldescription` / `toolautosubmit` / `toolparamdescription`); three tools (search-schools-by-name, find-zoned-schools-by-address, find-schools-in-neighborhood); inline forms on `/` and `/zoned` carry some of them, and `partials/_webmcp_global_forms.html` supplies the rest via `base.html`'s `{% block global_webmcp_forms %}` so **every page exposes all three**. Pages with inline duplicates re-include the partial inside `{% with webmcp_exclude=(...) %}` naming the duplicated toolnames — WebMCP requires unique toolnames per document, never a blanked block (that silently drops the rest of the tool set). (2) **Imperative tools** — `document.modelContext.registerTool()` (the settled home — the getter deliberately moved from Navigator to Document in Chrome 150; `navigator.modelContext` is the deprecated pre-150 name — feature-detect both via `document.modelContext ?? navigator.modelContext`) inline in templates that need to hand the agent page-specific context (DOM/URL aren't visible to in-browser chat panels). Lifecycle per the spec: `registerTool()` returns a Promise and rejects when its `AbortSignal` aborts; an AbortSignal is the ONLY unregistration path — `unregisterTool()`, `provideContext()`/`clearContext()`, and `ModelContextClient` were all removed from the proposal. `execute()` return contract: the normative IDL is `Promise<any>`, and every spec example returns a live object or an MCP `{content: [{type: "text", text}]}` array — never a pre-stringified JSON string — but Chrome's dev docs show string returns and that's what we ship (both verified working in Chrome 152). Keep JSON-string returns while the origin trial runs on Chrome's documented shape; flip to structured object returns when the proposed `outputSchema` (spec issues #9/#92) lands. School pages register two: `get_current_school_details` (call-first; identity always returns, big comparison blocks are opt-in via a composable `sections` param — default adds only `peer_ranks`, `all` returns everything) and `get_swd_outcomes_for_current_school` (special-ed questions only per its description). Chrome's size guidance: tool descriptions ≤500 chars, param descriptions ≤150, output lean — pinned by `test_school_page_imperative_tool_descriptions_are_lean`. (3) **Pre-visit manifest** at `/.well-known/webmcp` — declares the same three declarative-form tools as JSON so an agent can discover them without rendering the page. Source of truth is `_WEB_MCP_TOOLS` in `app/web/routes.py`; drift between manifest and form strings is caught by `test_webmcp_manifest_strings_match_form_partial` in `tests/test_webmcp.py`. Spec status (verified against the [spec repo](https://webmachinelearning.github.io/webmcp/) 2026-07): `/.well-known/webmcp` has NO spec future — zero mentions in the repo, and static tool manifests were explicitly considered and REJECTED as the discovery mechanism (they can't express dynamic, page-state-dependent tools). Direction of travel for pre-visit discovery is a Web App Manifest field plus just-in-time service-worker install, modeled on the Payment Handler API (`docs/service-workers.md` in the spec repo). Ours stays as a costless community convention (the [freeCodeCamp WebMCP guide](https://www.freecodecamp.org/news/a-developers-guide-to-webmcp/) documents the shape) — keep serving it, stop investing in it, watch the manifest-field proposal. (4) **Agent-invoked forms answer in place** — `base.html` has a capture-phase `submit` handler: when the event carries `agentInvoked` + `respondWith` (Chrome declarative API), it fetches the same endpoint with `format=json` and returns the payload to the agent instead of navigating. `/search`, `/zoned`, and `/neighborhood` serve that `format=json` branch from the same service calls as HTML — raw internal codes, no display filters, never an HTML error page (tests in `tests/test_agent_json.py`). Humans and non-WebMCP browsers keep normal navigation. Fragility note: `SubmitEvent.agentInvoked` + `respondWith()` are EXPLAINER-ONLY — not yet in normative spec text, and the cross-document form-response mechanism is the most-debated open area (spec issue #135) — this is the part of our stack most likely to change under us. `preventDefault()` must be called before `respondWith()` (our handler does).

- **WebMCP spec hard constraints and security rules (verified against the webmachinelearning/webmcp spec repo, 2026-07).** Hard constraints: tool registration rejects with `SecurityError` if `document.domain` was ever set (we never set it); the Permissions-Policy feature is named `tools`, default allowlist `'self'`; tool names are 1–128 chars of ASCII alphanumeric plus `_ - .` (all our names conform). Spec security guidance we adopt as house rules: (a) `untrustedContentHint` marks tool RETURNS carrying user-generated / third-party content — we deliberately omit it because every payload is first-party curated government data; mandatory the day we return user-authored text. (c) Keep tool input schemas minimal — agents will helpfully fill any extra parameter from the user's personal context, so an over-parameterized tool becomes silent profiling. - **NYC GeoSearch is unreliable, `geocode()` retries, and a 4xx is retryable.** Measured 2026-07-29: 5 of 15 identical requests for a valid address failed (400, 500, and a timeout), and the API went fully down twice in ~90 minutes. `geocode` makes `GEOCODE_ATTEMPTS` (3) attempts with exponential backoff and a 5s **per-attempt** timeout. **Retrying 4xx is deliberate, not sloppy:** GeoSearch answers an unknown address with `200` + an empty `features` array, so a 4xx is never a legitimate "no such address" — only upstream misbehavior. A definitive no-match (200/empty) stays a single call and is still cached; an exhausted failure is **not** cached, so a flaky window can't pin a bogus miss for the 24h TTL. Retry fixes *flakiness*, not an *outage* — httpx logs nothing on a timeout, so one log line can represent three attempts (an ~11s gap between tool call and a logged 4xx is the retry budget being spent, not a hang).
- **Geocode lookups are normalized and seeded; the old "never pre-warm the cache" warning is resolved.** The key was `" ".join(address.casefold().split())` — casefold and whitespace-collapse only — so punctuation and abbreviations survived as distinct keys and agents' rewrites all missed (**six spellings of one address** in a single day's logs: `428 W 26 St Manhattan`, `428 W 26th St, Manhattan`, `428 West 26th Street, New York, NY`, …). `normalize_address_key()` in `services/zoning.py` now collapses punctuation, ordinals, directionals, street-type abbreviations and trailing city/state noise. **The key is only ever compared to other keys, never sent upstream** (GeoSearch still gets the caller's original string), so consistent mangling — `St Marks Pl` → `street marks place` — is harmless; **collisions are not**, which is why ZIPs survive, noise is stripped only from the END, and a trailing `New York` is rewritten to `manhattan` only when no borough was named (`100 New York Ave, Brooklyn` keeps every token). `data/geocode-seed.json` is the durable layer — a reviewed, committed map of normalized key → coordinates, built by `scripts/build_geocode_seed.py`, **consulted before the network**. There is no Fly volume, so nothing written at runtime survives a deploy; a file in the repo does. Addresses don't move, so last-known-good is not a staleness risk. Refresh = re-run the script, review the diff. **The seed would short-circuit every respx-mocked geocode test**, so `tests/conftest.py` points `GEOCODE_SEED_PATH` at nothing by default; `test_committed_seed_covers_the_demo_address` is the one test that exercises the shipped file.

- **Numbered-school queries match structurally, not as fuzzy text — and the borough half is still open.** Most NYC schools are known by a level prefix plus a number, and users type both loosely. `_search_normalize` splits a glued prefix (`ps30` → `ps 30`, which previously returned **nothing**) before stripping leading zeros — that order matters, since `ps030` has no word boundary before the zeros. So an exact **number** match takes `NUMBER_MATCH_BOOST`, a matching prefix class adds `PREFIX_CLASS_BOOST`, and **both land before the `>= 80` cutoff** — the right school scores below the noise on fuzzy alone, so reordering survivors can't reach it. **Prefix is a boost, never a filter**: schools carry two (`P.S./I.S. 187`), and `clean_name` mangles that to `psis 187`, so `_name_prefix_classes` reads the RAW name where the punctuation survives. **Still open:** the borough word is not a borough signal. `"PS 321 Brooklyn"` is fixed as a side effect of the number boost, but `"PS 33 Manhattan"` surfaces the P.S. 033 schools in arbitrary borough order (10X033, a Bronx school, first).
